# 기존 분취 제어 프로그램 호환 검증 계획

대상: PyQt5 분취 제어 프로그램 (Chemyx RS-485 시린지펌프, 12/3-way 밸브, 분획수집기,
데드볼륨 물리모델 엔진, 스태거 시작, 라인상태 추적, 컴플라이언스 ODE, 세척 위상,
장비 시나리오 5종 — reaxus2/colosseum/novalve/nopush/onepump, 엔진 테스트 13 + 경계 35케이스)

## 호환의 정의

엔진 입장에서 RoboChem 펌프가 Chemyx와 **교체 가능**하면 호환.
검증 방법 = 엔진이 펌프에 요구하는 전제를 계약(contract)으로 명문화하고,
같은 계약 테스트를 양쪽에 돌려 둘 다 통과시키는 것.

## 비호환 축 7개와 어댑터의 흡수 방식

| # | 축 | RoboChem 특성 | 흡수 방식 | 검증 |
|---|---|---|---|---|
| 1 | 블로킹 vs 논블로킹 | write가 완료까지 블록 | 어댑터가 태스크를 전용 스레드로, start 즉시 리턴 | C1, C6 |
| 2 | 이동 중 상태조회 불가 | **블로킹 write 동안 시리얼 락 점유** (실측 확인) | 진행률 = 시간모델 추정 + 완료 시 실측 스냅. 기존 엔진도 시간모델 기반이라 구조 정합 | C3 |
| 3 | 리필 갭 | 유한 시린지, PumpVolume 리필 루프 중 유량 0 | pumping_event 샘플링 → refill_gaps 타임라인 노출. 유체 트래커가 갭만큼 시간축 보정. 정량 크리티컬 구간은 allow_refill=False + 사전 FillPump | C7 |
| 4 | 단위 | µL | 어댑터 경계에서 mL 통일 | C5 |
| 5 | 밸브 시맨틱 | 3포트 C/ON/OFF (C=시린지 고정) | set_valve('system'/'reservoir') 2상태로 축약, 기존 라인상태 추적기의 밸브 모델에 대응. 12-way는 별개 장치라 무간섭 | T3c |
| 6 | 정지 라이프사이클 | stop Event set 후 **명시적 clear 필수** | 어댑터가 stop→join→clear 자동 마감 | C4, E6 |
| 7 | 포트 탐색 | 장치당 USB CDC 다수 | known_devices.json 병행 (RS-485 버스와 독립). CH340 클론은 custom ID 필수 | serial_id |

추가 확인사항 (에뮬레이터 실측):
- FillPump 백래시 보정 −2% → 리필 직후 가용량 = 시린지의 98%. 엔진의 잔량 예측에 반영 필요
- 모터 블로킹 후 파이썬측 부기 desync → 복구 프로토콜 = 재제로잉(FillPump) 강제 (E2c/E2d)
- 에러 위계: 검증오류(송신 전) < 타임아웃 < 배드ack < 에러레지스터(MotorError 등 타입 디코드) — 엔진 에러정책에 매핑 가능

## 실행 단계

**1단계 (완료, 이 환경): 어댑터 쪽 계약 통과**
`compat_adapter.py` + `compat_contract_test.py` → 에뮬레이터 위에서 14/14 PASS.
계약 7개: 논블로킹 시작(1ms), busy 라이프사이클, 진행률 단조/스냅, 정지→부분토출→재사용,
단위 정합, 2펌프 스태거 동시구동, 리필 갭 노출.

**2단계 (실험실): Chemyx 쪽 계약 통과**
기존 Chemyx 드라이버를 같은 계약 인터페이스(start_dispense/busy/progress_ml/stop/wait/set_valve)로
감싸고 compat_contract_test를 실기로 실행. C7(리필 갭)은 Chemyx 구성에 리필이 없으면 N/A 처리.
→ 양쪽 통과 = 인터페이스 레벨 호환 입증.

**3단계 (실험실): 엔진 레벨 검증 — 기존 테스트 자산 재사용**
장비 시나리오에 'robochem' 추가 등록 (기존 5종 → 6종).
기존 엔진 테스트 13개 + 경계 35케이스를 **무수정으로** robochem 시나리오에 실행.
통과 기준: 기존 시나리오와 동일 패스율. 여기서 깨지는 케이스가 곧 엔진 가정과
RoboChem 특성의 실제 충돌 지점 — 특히 리필 갭이 스태거/데드볼륨 타이밍 계산에
들어가는지가 관건 (refill_gaps를 엔진 타임라인에 주입하는 훅 1개 예상).

**4단계: GUI 시뮬레이션 모드**
`_serial_iface`를 FakeSerial(에뮬레이터)로 주입하는 팩토리 분기 → 하드웨어 없이
GUI 전체 구동. 기존 프로그램의 시나리오 스위치에 'robochem-sim' 추가하면
사무실에서도 통합 개발 가능.

**5단계: 실기 교차검증**
에뮬레이터 tx_log와 실기 시리얼 로그 diff → 프로토콜 편차 확인.
steps_per_ml 실측 캘리브레이션 후 C5 정량 재검.

## 리스크 순위

1. (높음) 리필 갭 ↔ 스태거/유체트래커 타임라인 통합 — 엔진 훅 필요, 3단계에서 판명
2. (중간) 진행률이 추정치라는 점 — UI 차트는 문제없음(시간모델), 실측 의존 로직 있으면 완료 시점으로 이동
3. (낮음) 백래시 −2%, 에러정책 매핑, 포트 탐색 — 어댑터/설정 레벨에서 해결됨

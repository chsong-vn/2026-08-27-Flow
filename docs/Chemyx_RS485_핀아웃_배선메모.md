# Chemyx 시린지펌프 RS-485 배선 메모 (실측)

> 2026-07-28 실기로 확정. 선 해체 후 재조립 시 이 문서대로 다시 결선할 것.
> 각 펌프에 붙은 초음파 레벨센서 배선/맵핑은 [초음파레벨센서_배선메모.md](초음파레벨센서_배선메모.md) 참조
> (**핀 기준으로 관리** — 펌프 N → D(2N)/D(2N+1) → CSV index N−1).

## ★★★ 최종 확정 (2026-07-28 재검증 — 4대 O/O/O/O 재현)

```
어댑터 A  ←→  DB9 6번 & 9번
어댑터 B  ←→  DB9 1번 & 4번
```
반대로 꽂으면(1&4→A) **완전 침묵**. 헷갈리면 이 블록만 볼 것.

## ★ DB9 핀아웃 (핵심)

| DB9 핀 | 신호 | 어댑터 연결 |
|--------|------|------------|
| **1번, 4번** | **B (RX)** | 어댑터 **B** 단자 |
| **6번, 9번** | **A (TX)** | 어댑터 **A** 단자 |
| **5번** | GND | 어댑터 **GND** 단자 |

- **1번·4번을 서로 묶어서(브리지)** 어댑터 B로
- **6번·9번을 서로 묶어서(브리지)** 어댑터 A로
- 1&4, 6&9 브리지 = 데이지체인 통과(각 라인이 IN/OUT 두 핀에 나옴)

## 어댑터 / 통신 파라미터

- 어댑터: **중국산 RS-485/232 겸용 CH340 USB** → **485 모드**로 설정
- 포트: **번호가 계속 바뀜 — 고정값으로 믿지 말 것** (VID:PID=1A86:7523 CH340)
  - 2026-07-31 오전 **COM6** (LOCATION=1-3) 에서 4대 정상 → 같은 날 재배치 후 COM6 소멸, **COM9** (LOCATION=1-3.2.3) 로 이동
  - ⚠️ 12-way Runze 밸브도 **같은 CH340(1A86:7523)** 을 쓴다 → **VID/PID 로 구분 불가.** 프로토콜로 판별할 것:
    Chemyx = ASCII `"1 pump status\r"` 응답 / Runze = HEX 프레임(`CC .. DD`) 응답
  - ⚠️ `hardware_config.json` 의 Chemyx 4대는 **COM8** 고정 등록 → 앱 연결 전 실제 포트로 수정 필요
- **Baud 9600, 8N1** (8데이터/무패리티/1스톱)
- 펌프 주소(pump_id): **1, 2, 3, 4** (앞판넬에서 설정, 데이지체인)
- 명령 형식: `"<id> <command>\r"` 예) `1 pump status\r`

## ★ 반드시 지킬 것

1. **A/B 방향** (확정 요인) — 반대면 완전 침묵. 침묵이면 어댑터 A↔B 스왑해서 확인.
2. **접촉 견고하게** (확정 요인) — DuPont 점퍼 4노드 체인은 마진 없으면 계속 들락날락. 트렁크(A/B 2선)는 나사단자/납땜 권장. **ID1·ID2 깨끗 통신을 살린 진짜 원인 = A/B 방향 + 견고한 접촉.**
3. **GND(5번)** — 어댑터 GND에 결선. 2026-07-31 재배선 후 GND 결선 상태로 **응답 ASCII 깨짐 없이 정상 통신 확인**. (과거 이력: 이전 배선에서 GND 추가 시 비트 오류가 있었으나, A/B 방향·접촉 정리 후 재현되지 않음.)
4. **펌프 전원** — 정상 RS-485는 노드 하나 꺼져도 tri-state라 버스가 죽지 **않는 게 정상**(이론). 단, 펌프를 **커넥터째 뽑으면** pass-through 체인이 끊겨 하류가 죽고, 싸구려 트랜시버는 무전원 시 버스를 로딩할 수 있음. → **"전원 OFF만으로 전체 먹통"은 확인된 사실 아님**(당시 A/B 오류·접촉불량과 혼재). 그래도 모든 펌프 ON 권장.

## 펌프 명령 (help 실측)

- 이동: `start`, `stop`, `pause`, `restart`
- 설정: `set units [0,1,2,3]`, `set diameter [x.x]`, `set rate [x.x]`,
  **`set volume [x.x]` (+ = infuse/토출, − = withdraw/흡입)**, `set delay`, `set time`, `set primerate`
- 상태: `pump status`(0=idle), `dispensed volume`, `elapsed time`, `read limit parameter`
- ⚠️ **`view rate` / `view volume` 는 이 펌웨어에 없음** → "Command not recognized". 상태는 `pump status` / `dispensed volume` 사용.

## 통신 확인 방법 (스캔)

프로젝트 폴더에서 (py -3.14):
```python
import serial, time
ser = serial.Serial('COM5', 9600, timeout=0.2); time.sleep(2)
for pid in (1,2,3,4):
    ser.reset_input_buffer(); ser.write(f'{pid} pump status\r'.encode()); time.sleep(0.7)
    print(pid, ser.read(ser.in_waiting or 1).decode('ascii','replace'))
```
정상이면 `1 pump status \r\n0 \r\n>` 처럼 깨끗한 ASCII. 깨지면 신호 무결성(접촉/종단), 무응답이면 단선/전원/A-B스왑.

## 확정된 정상 배선

- 어댑터 485 모드, A→(6&9), B→(1&4), **GND→5번**, 스타 결선(모든 1&4 한 점, 모든 6&9 한 점)
- 펌프 4대 ON, 주소 1/2/3/4 **고유하게**

### 검증 이력

| 날짜 | 포트 | GND | 결과 |
|------|------|-----|------|
| 2026-07-28 | COM5 | 미결선 | ID 1/2/3/4 **O/O/O/O** |
| 2026-07-31 | COM6 | 결선 | ID 1/2/3 O/O/O, **ID4 무응답** (재결선 직후 1차) |
| 2026-07-31 | COM6 | 결선 | ID 1/2/3/4 **O/O/O/O** — 4라운드 반복 전부 깨끗 **(배선 확정)** |
| 2026-07-31 (재배치 후) | COM9 | 결선 | 4대 전부 무응답 — 어댑터 위치 이동(COM6→COM9), 펌프 전원/연결 미확인 상태 |

- 정상 응답 형태: `'4 pump status \r\n0 \r\n>'` (21B), `dispensed volume` 도 4대 전부 응답.
- **GND 결선 상태에서 비트 오류·깨짐 0건** → 이 배선에서는 GND 연결해도 문제 없음.
- 1차의 ID4 무응답은 재결선 직후 접촉이 자리잡기 전 일시 현상. 주소 0~9 전수 스캔에서도 4번이 안 보였으나 그대로 재시도하니 복구됨.
  → **ID4 침묵이 재발하면 주소 설정이 아니라 4번 분기 접촉부터 볼 것.**

## 프로토콜 실측 주의

- **명령 종단은 반드시 `\r`** — `\r` / `\r\n` 은 정상 응답, **`\n` 단독은 완전 무응답**.
- **보율은 9600 고정** — 19200/38400/57600/115200 전부 무응답(1번 대조군 포함) 확인.
- 유휴 상태에서 버스에 떠도는 트래픽 없음(무응답) = 폭주 노드 없음.

## ★★ 주소 중복 = 최대 함정 (실제 겪은 근본 원인)

- 증상: 특정 ID만 **매번 다르게 깨진 응답**(두 대가 동시 응답→RS-485 충돌) + 다른 ID는 무응답(빈 주소).
- 당시: 4번으로 만들려던 펌프가 실제론 **3에 남아** 진짜 3번과 충돌 → ID3 깨짐 + ID4 침묵. 주소를 4로 제대로 저장하자 **즉시 4대 전부 깨끗**.
- **깨짐이 랜덤(매번 다름)이면 충돌(주소 중복), 고정 패턴이면 배선** — 이걸로 구분.
- 앞판넬 주소 설정은 **저장 확인 필수** (저장 안 되면 재시작 시 옛 주소로 복귀 → "왜 자꾸 바뀌지?" 증상).
- 검증: 전원 껐다 켠 후 재스캔해서 1/2/3/4 유지 확인.

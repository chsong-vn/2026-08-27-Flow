# ⚠ 아웃렛 밸브 배선 반전 (invert) — 반드시 읽을 것

> **작성 2026-08-13.** 나중에 반드시 문제의 여지가 있는 사항이라 기록해 둔다 (사용자 지시).
> 재배관·밸브 교체·펌웨어 재플래시·수집 이상 디버깅 때 이 문서를 먼저 확인할 것.

## 무엇을 했나

- **물리 상태**: 아웃렛 3-way 밸브(ESP32 ch5)의 **collector 라인과 waste 라인이 반대로 체결**되어 있다 (2026-08-13 확인).
- **소프트웨어 흡수**: 재배관 대신 `hardware_config.json` 의 아웃렛 장치(`dev_esp32v_5`)에
  `"invert": true` 를 두고, ESP32EthValve 드라이버가 **와이어 명령만 1↔2 반전**해서 보낸다.
- **논리 의미는 불변**: 엔진/타이머/Manual 탭/배관도가 보는 위치는 전부 "논리 위치"
  (1=WASTE, 2=COLLECT) 그대로다. `valve.position` 도 논리 값. 마지막 실제 전송값은
  `valve.wire_position` (디버깅용).

```
논리 WASTE(1)  → 와이어 2 전송 → (반대 체결된) 물리 waste 방향   ✓
논리 COLLECT(2) → 와이어 1 전송 → (반대 체결된) 물리 collector 방향 ✓
```

## ⚠ 남아있는 위험 (이것 때문에 기록함)

1. **무전원/부팅 기본 경로가 COLLECT 쪽**: 릴레이 OFF(부팅·정전·앱 미실행) 상태의
   물리 유로가 이제 **collector 방향**이다 (반전 전에는 waste = 안전 방향이었음).
   정전·비상 시 자연 배수가 수집 플레이트로 갈 수 있다. → 근본 해결은 물리 재배관뿐.
2. **재배관 시 이중 반전**: 나중에 튜브를 올바르게 다시 체결하면
   **config 의 `"invert": true` 를 반드시 제거**해야 한다. 안 지우면 반대로 동작
   (예전과 같은 증상이 다시 나타나면 이 문서부터 의심).
3. **펌웨어 STATE/실측 조회는 와이어 기준**: `query_state()` 가 돌려주는 릴레이 상태는
   원시(와이어) 값이라 논리 위치와 반대다. 디버깅 때 헷갈리지 말 것.
4. **ESP32 재플래시/보드 교체 시**: 펌웨어 릴레이 극성(RELAY_ACTIVE_HIGH)까지 바뀌면
   반전이 중첩될 수 있다 — 플래시 후 Manual 탭에서 COLLECT/WASTE 실물 방향을 눈으로
   재확인할 것.

## 부팅 시 확인 방법

앱 시작 로그에 다음 경고가 떠야 반전 모드가 적용된 것:

```
⚠⚠ [Outlet] 배선 반전 모드(invert) — collector/waste 튜브가 반대로 체결된 상태를 SW 로 흡수 중...
```

이 경고가 **안 뜨는데** 수집이 반대로 나가면: config invert 누락. 경고가 **뜨는데**
반대로 나가면: 그 사이 누가 재배관함 → invert 제거.

## 원복 절차 (물리 재배관 시)

1. 앱 종료 → collector/waste 튜브를 올바르게 재체결
2. `hardware_config.json` → `dev_esp32v_5` 의 `"invert": true` 줄 삭제
3. 앱 시작 → 경고 미출력 확인 → Manual 탭에서 COLLECT/WASTE 실물 방향 육안 확인
4. 이 문서 상단에 원복 날짜 기록

## 관련 코드

- 드라이버: `hardware/valves/valve_esp32_eth.py` (`invert` 파라미터, `wire_position`)
- 배선: `core/hw_manager.py` 아웃렛/스위처 생성부 (`o_info.get("invert")`)
- 설정: `hardware_config.json` inventory `dev_esp32v_5.invert`

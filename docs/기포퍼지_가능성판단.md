# 소스라인 기포 퍼지 — 가능성 판단 (2026-08-14)

> **이 폴더(`20260805 Flow - gas`)는 실험 브랜치다.** 원본 `20260805 Flow` 는 손대지 않았다.
> 롤백 = `bubble_purge_enabled: false` 로 끄거나, 이 폴더를 통째로 삭제.

## 문제

바이알↔12way 구간의 초기 잔재 공기가 매 런 시약과 함께 반응기로 들어가 반응 속도에
영향을 준다(사용자 실기 관측).

현행 코드에서 이 공기를 빼주는 주체가 **아무도 없다**:

- `line_src`(= inlet + selector + valve_pump)는 [strict_engine.py:1714](../engine/strict_engine.py)
  에서 계산되지만 **타이밍 산식에만** 쓰인다.
- 커밋 `d572719`(소스퍼지 무효화, `purge_order=lifo`)로 퍼지 **동작**은 이미 껐다.
- 2026-08-14 세션의 왕복레그 제외(흡입 2.99→1.16)로 **흡입량에서도** 빠졌다.

## 제안 로직 (사용자)

> 반응기 세척·프리필 **전에**, 12way 시약 포트에서 데드볼륨만큼 흡입한 뒤
> 그 기포를 12way(폐액 포트)로 배출한다.

## 판단: **성립한다** — 단, 퍼지량 정의에 함정이 하나 있다

`tests/test_source_bubble_purge.py` 23항목 ALL PASS (실엔진 + mock 하드웨어 3스텝 구동).

### 퍼지량 — 요건은 "12way 로터 통과"

| 구간 | 실측 (mL) | 퍼지에 필요? |
|------|-----------|------------|
| inlet (바이알→12way) | 0.0754 | ✅ 기포 최대 길이 |
| selector (12way 내부) | 0.0224 | ✅ 로터 통로 |
| valve_pump (12way→3way→시린지) | 0.0597 | ❌ 불필요 |
| **이론 최소량 = inlet + selector** | **0.0978** | |
| **실사용 = ×factor 2.0** | **0.1956** | |

되밀 때 **로터 하류**(valve_pump·배럴)에 있는 것은 전부 port 12 로 빠지고,
**로터 상류**(시약 포트 인렛)에 남은 것만 갇힌다. 따라서 기포가 배럴까지 갈
필요는 없고 로터만 통과하면 된다 — 초기 구현(전체 경로 0.1575)은 과했다.

**단, 이론 최소량으로는 실제로 안 빠진다** (2026-08-14 사용자 실기 관측 —
1.0 은 물론 1.5 로도 기포 잔존). 이론값이 부족한 이유:

- 기포는 **압축성**이 있어 흡입 중 팽창했다가 되밀 때 수축 → 실제 이동거리가 명목 부피보다 짧다
- 잔재 공기는 깔끔한 슬러그 하나가 아니라 **여러 작은 기포로 분산**돼 이론 길이(=inlet 부피)보다 훨씬 긴 구간에 퍼진다
- **벽면에 붙은 기포**는 전단이 약하면 슬러그와 같이 안 움직인다

→ `bubble_purge_factor` 기본 **2.0** (= 0.1956mL). 이 값이면 기포 뒷단이 로터에서
0.0978mL 떨어져 valve_pump(0.0597)를 넘어 배럴 안까지 들어온다. 엔진 클램프 1.0~4.0.

### ★ 함정 — 소프트웨어 하한이 조용히 삼킨다

`ChemyxSmartPump.refill_prepare` 는 `fill_vol < 0.1` 이면 **로그 없이 스킵**
(`return False`)했다. 최소량 0.0978 은 하한 미만 → 고쳤다고 믿는데 무동작.

이 하한은 원래 "거의 찬 시린지에 무의미한 탑업 금지" 가드였는데(스킵 로그 문구가
그 의도를 드러낸다) 명시적 소량 요청까지 같이 삼켰다. gas 브랜치에서
`system_params.refill_min_vol_ml` (기본 0.1, 여기선 **0.05**)로 분리하고,
스킵 사유를 '시린지 가득' vs '요청이 하한 미만'으로 나눠 후자는 ⚠ 경고로 출력한다.

부수 효과 — 기존 지뢰 하나가 같이 풀린다: Phase-0 정량 리필에서 잔량이 남아
`need` 가 0.005~0.1 사이면 (예: 분기 데드볼륨 0.277, 잔량 0.2 → need 0.077)
**조용히 스킵**되어 분기가 덜 찬 채로 진행됐다.

### 순서: 퍼지 → 시스템 세척 → 프리필

퍼지가 끝나면 공용 구간(12way→3way→시린지, 0.0597)에 시약이 남는다. 뒤따르는
세척(port1 흡입 → port12 배출)이 그 구간을 헹궈낸다. **퍼지를 세척 뒤에 두면**
그 잔류 시약이 그대로 Phase-0 용매와 섞인다. 그래서 Step 1.9 (세척 앞)에 넣었다.

### 비용

포트당 **0.1956 mL × 펌프수** 가 폐액으로 나간다 (2펌프 = **0.391 mL/포트**).
factor 를 올린 만큼 시약 손실이 선형으로 늘어난다 — 극소량 시약 실험에선
`bubble_purge_enabled: false`, 또는 factor 를 낮추고 세척 사이클로 보완할 것.

## ⚠ 이 퍼지가 **원인이 아닐 수 있다** — 먼저 확인할 것

inlet 구간은 **0.0754 mL 뿐이다.** 이건 1회성 예산이지 발생원이 아니다.
관측되는 기포가 이보다 뚜렷하게 많거나 **매 스텝 반복**된다면 원인은 다른 데 있고,
이 퍼지로는 해결되지 않는다. 연속 발생원 후보:

| 후보 | 특징 | 확인법 |
|------|------|--------|
| 바이알 니들이 액면 위 / 시약 고갈 | **무한 공급원** — 흡입할 때마다 공기 | 니들 침지 깊이·잔량 육안 |
| 흡입 감압에 의한 탈기(용존기체 석출) | 휘발성 용매·높은 흡입 속도에서 심함 | `syringe_refill_rate` 4.0 → 2.0 으로 낮춰 비교 |
| 피팅/루어 미세 누설 | **흡입 때만** 공기 유입, 가압 땐 액 안 샘 → 눈에 안 띔 | 흡입 중 피팅에 용매 한 방울 → 빨려드는지 |
| 시린지 플런저 씰 마모 | 특정 채널에서만 재현 | 채널 교차 비교 |

**가장 싼 판별법**: 이 퍼지를 켠 채로 2스텝 이상 돌린다.
- 스텝1만 깨끗하고 스텝2+ 도 깨끗 → **inlet 잔재 공기가 맞다** (해결).
- 스텝2+ 에서 기포가 같은 양으로 다시 나옴 → **연속 발생원**. 퍼지는 무관하니
  위 표로 넘어갈 것. (퍼지는 포트당 1회라 스텝2+ 엔 개입하지 않으므로 깨끗한 대조군이 된다.)

## 실기에서만 판정 가능한 잔여 불확실성

1. **기포 위치 가정** — 잔재 공기가 정말 inlet 구간에 있는지. 바이알 니들 끝이
   액면 위로 나와 흡입 중 공기를 새로 빨아들이는 경우는 이 퍼지로 해결되지 않는다.
2. **되밀기 속도** — 배출은 `wash_speed`(15 mL/min)를 쓴다. 이 속도에서 기포가
   12way 를 확실히 통과하는지 미확인. 필요 시 전용 rate 파라미터 추가.
3. **공용 구간 잔류 시약** — 퍼지 후 valve_pump 의 시약 0.0597mL 를 뒤따르는 세척이
   충분히 제거하는지. 교차오염이 보이면 `bubble_purge_factor` 대신 세척 사이클 증설.
4. **회계 미반영** — `_purged_ports` 는 `_primed_ports` 와 별도로 관리한다(퍼지 후에도
   `line_src` 타이밍 산식은 그대로). 현재 `purge_order=lifo` 라 소스퍼지 타이밍이
   미적용이므로 실효 차이는 없지만, `fifo` 로 되돌리면 재검토 필요.

## 설정

`hardware_config.json` → `system_params`:

```json
"bubble_purge_enabled": true,
"bubble_purge_waste_port": 12,
"bubble_purge_factor": 2.0,
"refill_min_vol_ml": 0.05
```

`refill_min_vol_ml` 은 퍼지 전용이 아니라 **모든 리필의 최소량**이다 (원본 기본 0.1).
원본으로 되돌리려면 이 키를 지우거나 0.1 로 둔다.

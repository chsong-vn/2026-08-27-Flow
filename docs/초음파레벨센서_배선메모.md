# 초음파 레벨센서 (HC-SR04 4ch) 배선 메모 — 실측

> 2026-07-31 기준. 센서 재장착/재배선 시 이 문서대로 결선할 것.
> 펌프 통신 배선은 [Chemyx_RS485_핀아웃_배선메모.md](Chemyx_RS485_핀아웃_배선메모.md) 참조.
>
> **센서에 붙인 "1·2·3·4번" 라벨은 쓰지 않는다.** 라벨은 사람이 임의로 붙인 것이라
> 역순으로 꽂아도 표기상 티가 안 났다(실제로 그래서 어긋났음).
> **기준은 아두이노 핀 번호** — 펌웨어 배열과 1:1로 고정돼 오해가 생기지 않는다.

## ★★★ 배선 맵 (핀 기준)

| 아두이노 핀 (TRIG/ECHO) | **CSV 열 = index** | **Chemyx 펌프** | 그룹 |
|------------------------|-------------------|----------------|------|
| **D2 / D3** | **0** | **펌프 1** | Group A |
| **D4 / D5** | **1** | **펌프 2** | Group_B |
| **D6 / D7** | **2** | **펌프 3** | Group_C |
| **D8 / D9** | **3** | **펌프 4** | Group_D |

**핀 순서 = index 순서 = 펌프 번호 (전부 정순).** 외우기 쉬운 이 정렬이 정답이다.

- index 는 펌웨어 `PIN_TRIG[] = {2,4,6,8}` / `PIN_ECHO[] = {3,5,7,9}` 배열 순서 그대로 = **D2 가 0열**.
- 드라이버 `ultrasonic_level.py` 는 채널 설정의 `index` 로 CSV 해당 열만 골라 median 낸다.
- 즉 **펌프 N → D(2N) / D(2N+1) → index N−1**.

## ⚠️ 현재 실물 배선은 역순 — 수정 필요

2026-07-31 확인 시점의 실제 결선은 위 표와 **거꾸로** 였다 (D2/D3 ↔ 펌프 4, D8/D9 ↔ 펌프 1).

- **조치: 실물 배선을 위 표대로 정순으로 바꾼다.** (config 를 역순에 맞추지 않는다 —
  정순이 기본값과 일치해 이후 채널 추가 시 실수가 줄어든다.)
- 배선을 정순으로 고치면 `hardware_config.json` → `roles.pumps[0]`(Group A = 펌프 1) 의
  `"level_channel_index": 0` 이 **그대로 맞다. config 수정 불필요.**
- 재배선 후 반드시 **채널 격리 확인**: 한 채널 앞만 손으로 가려서 그 열만 값이 변하는지 본다
  (아래 "재배선 후 확인 절차" 참조). 역순이면 엉뚱한 열이 반응한다.

### 캘리브레이션은 재확인 대상

현재 config 의 `level_cal_slope: 1.06776` / `level_cal_intercept: -9.2382` 는 **CH0 에서 측정된 값**인데,
측정 당시 CH0 에 물려 있던 게 어느 펌프였는지 확정되지 않았다(역순 배선이었다면 펌프 4).

- 재배선 후 **펌프 1 기준으로 0점만이라도 재확인**할 것 — 빈 시린지에서 환산값이 0 근처(±수십 µL)인지.
- 어긋나면 `calibrate_ch0.py` / `level_cal_helper.py` 로 다시 뜬다.
- HC-SR04 는 개체차 ±3mm 급이고 반사블록 장착 높이도 펌프마다 달라, **센서를 바꿔 물리면 캘리브레이션은 따라오지 않는다.**

### Group_B/C/D 는 소프트웨어 미등록

`roles.pumps[1~3]` 에는 `drivers.level` 슬롯 자체가 없다 → 센서 3대가 물리적으로 붙어 있어도
엔진은 **Group A 것만 읽는다**. 나머지도 쓰려면 각 펌프에 level 슬롯 + index(1/2/3) + 개별 캘리브레이션 필요.

## 하드웨어 / 프로토콜

- 보드: **Arduino Uno**, VID:PID = **2341:0043**, SER=14101
- 포트: **COM3** (2026-07-31 실측 — 재연결 시 번호 바뀜, **VID 로 식별할 것**)
- **9600 bps**
- 펌웨어: `hardware/sensors/firmware/level_sensor_hcsr04_4ch/level_sensor_hcsr04_4ch.ino`
- 출력: 매 스윕 한 줄 CSV `"d0,d1,d2,d3\n"` (cm, 소수 2자리), 에코 없으면 해당 열 `NA`
  - 예: `12.34,NA,8.90,45.60`
- 스윕 주기 100ms(≈10Hz), 채널 간 8ms 간격(크로스토크 방지), 에코 타임아웃 30000µs(≈5m)
- **전원: 외부 5V → 각 센서 VCC, 외부 GND ↔ 아두이노 GND 공통 접지 필수**

## 검증 이력

| 날짜 | 포트 | 결과 |
|------|------|------|
| 2026-07-31 | COM3 | 펌웨어/프로토콜 **정상**(40줄 수신, 형식오류 0) / **4채널 전부 `NA`** — 에코 없음 |
| 2026-07-31 | COM3 | 재측정 동일(전부 NA) → **원인 = 센서 전원 미연결** (사용자 확인). 전원 인가 후 재측정 필요 |

2026-07-31 수신 원문: `'NA,NA,NA,NA'` (40줄 연속 동일)

**진단**: CSV 형식이 정확히 나오므로 UNO·펌웨어·시리얼은 정상. `NA` 는 `pulseIn` 타임아웃 = 에코 미수신.
4채널이 **동시에** 죽은 것이라 채널 개별 원인(반사블록 정렬 등)보다 **공통 원인** 이 유력:

1. **HC-SR04 외부 5V 전원 미인가** (가장 유력 — 4개 동시 사망의 자연스러운 설명)
2. **외부 GND ↔ 아두이노 GND 공통 접지 누락** — 전원이 있어도 기준전위가 없어 전부 무반응
3. ECHO 배선 탈락(4개 동시는 가능성 낮음) 또는 반사블록이 측정 범위 밖

→ 다음 조치: **센서 VCC 5V 와 공통 접지부터 확인.**

## 재배선 후 확인 절차

```
py -3.14 check_level4ch.py COM3
```

1. **전 채널 값이 나오는지** — `NA` 가 남으면 그 채널의 전원/ECHO 배선
2. **채널 격리(정순 확인)** — 한 채널 센서 앞만 손바닥으로 10cm쯤 막고 다시 실행.
   **막은 펌프의 index 열만** 값이 확 줄어야 정순. 다른 열이 변하면 아직 어긋난 것.
   - 펌프 1 막음 → CH0 만 변화 / 펌프 4 막음 → CH3 만 변화
3. **CH0 0점** — 펌프 1 시린지를 비운 상태에서 환산값이 0 근처인지 (캘리브레이션 유효성)

판정 기준은 드라이버와 동일하게 맞춰져 있다 — **유효표본 50% 미만이면 실패**
(`ultrasonic_level.py` `_read_raw` 품질 게이트), 산포 ±1cm 초과면 반사블록/정렬 경고.
